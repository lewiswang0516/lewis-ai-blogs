这篇写给想弄明白 AI 到底怎么收费的人，不管你是按月订阅还是按量调用 API。建议先读第 01 篇，知道大模型是在“一个词一个词往下接”。

很多人第一次被 AI 的账单或者额度吓到，都是同一个反应：我也没问几句啊。

问题出在“几句”这个计量单位上。AI 不按句子收费，也不按问题收费，它按 token 收费。而且你以为只发了一句话，它实际处理的可能是几万个 token。这篇就把这件事从头讲清楚。

## token：AI 读写文字的单位

token 是模型处理文字的最小单位。模型不是一个字一个字、也不是一个词一个词地读，而是先把文字切成一块一块的 token，再去处理。

切法由模型的分词器（tokenizer）决定。英文里一个常见单词通常是一个 token，长词会被拆成几块；中文的切法不太一样，一个汉字可能是一个 token，也可能更多，常见词组有时会合成一块。

有两点值得知道：

第一，不同模型的分词器不一样，同一段文字在不同模型上算出来的 token 数不同。Anthropic 的定价文档里就提到，Claude 4.7 及之后的模型换了新的分词器，同样的文字会比以前多出大约 30% 的 token。

第二，官方给的换算比例大多是按英文估的。Anthropic 说在当前分词器上，100 万 token 大约相当于 55.5 万个英文单词、250 万个字符。中文的比例要你自己测。

日常使用不需要精确换算，记住“token 是计费单位，文字越多 token 越多”就够了。

## 账单上的几种 token

按量付费时，一次请求的账单通常分成这几块。下面用 Anthropic 2026 年 11 月的官方价格举例，单位是美元每百万 token：

| 模型 | 输入 | 输出 | 缓存读取 | 5 分钟缓存写入 |
| --- | --- | --- | --- | --- |
| Claude Opus 5.5 | 4 | 20 | 0.20 | 5 |
| Claude Sonnet 5.5 | 2 | 10 | 0.10 | 2.50 |
| Claude Haiku 5.5（10 万 token 以内） | 0.10 | 0.50 | 0.01 | 0.125 |

一个一个说。

**输入**：你发给模型的所有内容，不只是你刚打的那句话，后面会讲到还包括什么。

**输出**：模型写给你的内容。可以看到，输出单价是输入的 5 倍，这在各家基本都是这个规律，OpenAI 和 Google 的主力模型也是输出比输入贵好几倍。

**思考**：现在的模型回答前大多会先“想一想”，这部分思考内容也按输出计费。Google 的价格表上写得很直白：输出价格包含思考 token。所以思考强度开得越高，花得越多。

**缓存读取和写入**：这两项是省钱的关键，下面单独讲。

另外，各家还有一些附加规则。比如 Claude Haiku 5.5 超过 10 万 token 的请求按更高的价格算；OpenAI 的 GPT-6.2 系列输入超过 27.2 万 token 时，输入单价翻倍；批量处理（Batch API）各家一般打五折，适合不着急要结果的任务。

## 上下文：它这一次能看见的全部内容

理解计费，最关键的是“上下文”这个概念。

上下文是模型在一次请求里能看到的所有内容：系统提示、你之前说的每一句话、它之前回的每一句话、你贴进去的文件、它调用工具拿到的结果，最后才是你刚打的那句话。

上下文窗口就是这个“能看见”的上限。截至 2026 年 11 月，Claude 当前几款模型、Gemini 4 系列都是 100 万 token，OpenAI 的 GPT-6.2 系列是 105 万。单次输出的上限另算，Claude 和 GPT-6.2 都是 12.8 万 token。

第 01 篇说过，模型本身不记得任何事。你们“聊了半天”，它之所以接得上，是因为聊天软件每次都把之前的全部对话打包，和你的新消息一起重新发过去。

这就是“我也没问几句”的答案。假设一个对话已经积累了 5 万 token，你再问一句“那这个变量叫什么”，这一句可能就十几个 token，但这次请求的输入是 5 万多。对话越长，每一句话的“底价”越高。

用 AI 编程工具时，这个效应会被放大。它每读一个文件、每跑一条命令，结果都会进入上下文；而且它干一件事往往要调用很多次工具，每调用一次就是一次带着全部历史的新请求。

## 缓存：重复的部分便宜算

既然每次都要重发一大段一模一样的历史，能不能别每次都全价算？这就是提示缓存（prompt caching）。

原理很简单：如果这次请求的开头和上次一模一样，服务端可以直接复用上次处理好的结果，这一部分按便宜得多的价格算。看上面那张表，Sonnet 5.5 的缓存读取是 0.10 美元，只有正常输入的 5%。

算一笔账。假设用 Sonnet 5.5 发一次请求，输入 5 万 token，输出 2000 token：

- 没有缓存：输入 0.05 × 2 = 0.10 美元，输出 0.002 × 10 = 0.02 美元，合计 0.12 美元
- 前 4.8 万 token 命中缓存：缓存读取 0.048 × 0.10 ≈ 0.005 美元，新增的 2000 token 按缓存写入价算 0.002 × 2.50 = 0.005 美元，输出还是 0.02 美元，合计约 0.03 美元

同一次请求，差了大约四倍。长对话之所以还用得起，靠的就是缓存。

缓存有两个限制要记住：

一是它只认开头。必须从第一个字开始一模一样，中间改了一处，从那儿往后都得重新算。

二是它会过期。Anthropic 的缓存写入分 5 分钟和 1 小时两档，1 小时那档写入更贵；OpenAI 的缓存写入价格对应 30 分钟保留期。离开一阵再回来，缓存可能已经没了，第一句话就是全价。

什么操作会打断缓存、怎么避开，第 09、10 篇会专门讲，这里先知道有这么回事就行。

## 订阅和按量付费，是两套算法

上面说的都是按量付费，也就是直接调用 API 的算法。大多数个人用户用的其实是订阅。

以 Claude 为例，2026 年 11 月的官方价格是：Pro 每月 20 美元（按年付折合每月 17 美元），Max 每月 100 美元，Ultra 每月 200 美元。订阅不按 token 扣钱，而是给你一个用量额度：每 5 小时一个额度，每周还有一个总额度。Max 是 Pro 的 5 倍，Ultra 是 Pro 的 10 倍周额度，并且认证过的账户没有 5 小时限制。Free 版也能聊天，但不包含 Claude Code。

OpenAI 的 Codex 也类似，包含在 ChatGPT 的各档订阅里。Plus 这类档位按每 5 小时估算用量，另外可能还有周限额。

订阅的额度虽然不直接显示成 token，背后的逻辑是一样的：上下文越长、模型越大、思考越深、缓存命中越少，额度掉得越快。所以下面这些概念，对订阅用户同样有用。

## 怎么看自己用了多少

按量付费的话，各家控制台都有用量页面，能看到每天花了多少、输入输出各多少。

用 Claude Code 的话，有两个命令很实用：`/usage` 看当前会话的花费和套餐额度的使用情况，订阅用户还能看到额度都花在了哪些地方；`/context` 用一张彩色格子图显示上下文现在被什么占着。

建议你现在就去看一眼自己的数字。看过一次，你对“一句话到底花多少”就有感觉了。

## 小结

把这篇压缩成几句话：

- token 是计费单位，输出比输入贵好几倍，思考按输出算
- 每次请求都会把整个上下文重发一遍，所以对话越长，每句话越贵
- 缓存让重复的开头便宜很多，但它只认开头，而且会过期
- 订阅不按 token 扣钱，但额度消耗的逻辑一样

知道钱花在哪儿之后，怎么省就是另一个话题了。第 09、10 篇以 Claude Code 为例，专门讲五个省 token 的习惯，包括什么时候开新会话、怎么不打断缓存、什么时候把活交给子代理。
